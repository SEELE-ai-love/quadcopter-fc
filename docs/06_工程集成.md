# 06 CubeMX 工程与源码集成

本文说明如何把仓库中的 `Algorithm/`、`Hardware/`、`System/` 源码接入一个 STM32F405 CubeMX + Keil 工程。仓库只保留自研代码与仿真，不提交 CubeMX 自动生成的大量 HAL/FreeRTOS 文件。

## 1. CubeMX 基础配置

1. 新建工程，芯片选择 `STM32F405RGTx`；
2. RCC：`HSE Crystal`，SYSCLK `168 MHz`；
3. SYS：Debug 选 `Serial Wire`；
4. 中间件：启用 FreeRTOS（CMSIS-RTOS v2）；
5. 外设按开发阶段逐步打开：
   - 上电自检：USART1（PA9 TX / PA10 RX，115200）；
   - IMU：I2C1（PB6 SCL / PB7 SDA），ICM-20948 挂在 I2C1；
   - 电机：TIM8 四通道（PC6-PC9）输出 DShot300 帧；
   - 定高：UART5（PC12 / PD2）接收向上激光；
   - 定点：UART2（PA2 / PA3）接二维雷达，或 UART3（PB10 / PB11）接光流；
   - 遥控输入：按实际接收机方案配置，文档默认先保留 PS2 接收机占用的 USB Host 引脚。

具体引脚以板子丝印与自己的原理图为准；`docs/01_硬件平台.md` 中的表格是第一版资源分配。

## 2. 添加源码

Keil 工程中新建三个 Source Group 并加入：

| Group | 源码 |
| ---- | ---- |
| `Algorithm` | `../Algorithm/*.c` |
| `Hardware` | `../Hardware/*.c` |
| `System` | 公共头文件（无需 `.c`） |

Include Path 加入仓库根目录下的三个源码目录：

```text
../Algorithm
../Hardware
../System
```

编译宏沿用 CubeMX 生成内容（`USE_HAL_DRIVER`、`STM32F405xx` 等），不要在自研源码里写死板级调用。

## 3. 应用层接入方式

自研模块通过函数接口和回调接口被调用，不直接依赖 HAL：

- `fc_icm20948_t` 需要工程层提供 `read` / `write` 两个 I2C 回调；
- 姿态、控制、混控、安全、高度模块只在任务体内调用；
- 只有 `fc_safety` 能决定电机输出是否允许到达 DShot 驱动；
- FreeRTOS 任务划分与周期见 `docs/02_软件架构.md`。

## 4. 构建顺序与验收

按 `docs/04_开发路线与验收.md` 的阶段执行。每个阶段只打开对应外设，避免一次接入过多模块后难以定位问题。实机测试前必须阅读并遵守 `docs/05_安全与调参.md`。
