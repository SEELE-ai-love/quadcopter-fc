# IMU 软件 FIFO：本次接入说明

## 这次用了什么

采用16帧的静态环形数组，遵循先入先出。每帧是 `AttitudeSnapshot_t`，包含同一轮的姿态、角速度、加速度、读数完成时刻和序号。它是已完成姿态解算的IMU历史快照，不是ICM20948芯片的硬件FIFO，也不是原始ADC数据FIFO。

```
attitude_task：200Hz读取IMU → 原EKF/Mahony解算 → 最新快照 + 软件FIFO
                                                            ↓
Control_task：200Hz调用LC307_EstimatorUpdate → 逐帧IMU预测 → 一次最新光流校正
                                                            ↓
                                                 原位置PD、姿态PID和混控
```

- 姿态任务仍200Hz，采样寄存器、单位、偏置、坐标方向不变。
- 姿态算法原来的固定dt=0.005s保持不变；这次没有把姿态解算改成真实dt或预积分。
- 时间戳改在成功读取IMU后立即取得，不再等解算结束才标记；它仍是软件读数完成时刻，不是传感器内部采样时刻。
- FIFO保存已经读到的样本，无法补回两次I2C读取之间被芯片输出寄存器覆盖的样本。
- 正常生产和消费都是200Hz，大多数周期只有一帧；FIFO的作用是在短暂调度延迟时保留历史，不是自动提高采样率。

## 时间、满队列与恢复

- 位置预测dt继续使用相邻样本原有 `sample_tick` 的差值，不能用本次出队时刻代替。
- 本轮只消费开始时已有的帧数，最多16帧；不无限追赶生产者。
- 一批样本的非末帧只做预测，末帧才允许用最新光流校正。0.95/0.05公式、原光流符号、旋转补偿、重力补偿和死区不变。
- FIFO空时只沿用已出队的末帧校正新光流，不抢读可能刚入队的新快照；同一IMU序号不重复预测。不同序号时间相同仍是dt=0，不伪造时间戳。
- 满时丢最老帧、记录overflow，保留较新的样本。16帧约可存80ms，但仍遵守原25ms新鲜度/积分间隔限制，不会因为有80ms缓冲就允许补80ms积分。
- 已跟踪状态发现序号缺口或间隔大于25ms，撤销估计有效状态，保留位置、速度和历史速度；等待新光流观测重新建立跟踪。恢复第一帧不跨缺口积分。
- 原100ms光流超时、位置控制启停/故障状态机、电机禁用开关和Yaw捕获均保留。
- FIFO只允许Control中的位置估计器Pop；其他任务继续用GetSnapshot/GetLatest，不要再写第二个Pop消费者。

## 临界区与内存

入队复用原发布快照临界区，包含一帧复制、索引和计数更新，不再嵌套临界区。Pop每次也只复制一帧。三角函数、滤波、积分和打印都在临界区外。

当前32位Tick配置下，每帧44字节，16帧数组704字节，另有44字节末帧缓存及索引/统计/对齐；没有在Control栈上放16帧数组。最终实际占用以编译器map为准。

## 人类如何观察

`Attitude_FifoGetStats()`可读取快照，调试器也可查看静态变量 `g_attitude_fifo_stats`。此次没有默认开启新的串口打印；`LC307_PrintDiagnostics()`中留有整组注释的 `IMU FIFO` 每秒诊断，需观察时整组取消注释即可，已有互斥锁继续复用。

| 字段 | 含义 | 正常观察趋势 |
|---|---|---|
| pushed | 成功读取并解算后入队总数 | 约每秒增加200，以实际任务运行情况为准 |
| popped | 已取出总数 | 大体跟随pushed；取出不代表都通过估计检查 |
| pending | 当前未取帧数 | 通常0～1，短暂可能更多 |
| high_water | 积压历史最大值 | 不超过16 |
| overflow | 满时丢弃老帧累计数 | 正常应不增长 |

统计关系（计数未回绕时）：pushed = popped + pending + overflow。

如需用已有LC307每秒诊断打印观察，可在现有打印互斥锁内取统计并打印整数；不要另起高频printf，也不要在临界区里打印。

原 `LC307 RATE` 中predict仍统计成功积分的IMU样本，correct统计实际用过的新光流帧。正常连续工作时分别约200/s和50/s。imu_gap现在也包含IMU序号缺口，单独看overflow才能区分是否FIFO已满。

本轮未编译、未运行测试、未烧录；硬件效果需要人类重新确认。此前对旧版频率与PD方向的观察不能代替本次FIFO接入后的验证。
