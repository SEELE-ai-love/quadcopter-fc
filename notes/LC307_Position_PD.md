## 当前实测方向与单位

从机身上方向下看：

- 平移：X正向右，Y正向前。
- 姿态：Roll正是抬头，Pitch正是右压。这是本项目命名，不按常见飞控名称自行交换。
- Gyro：保持项目中已验证的轴、符号和旋转补偿，不因名称重新改映射。
- 光流原始映射：`flow_rate_x=flowX/10000/dt`，`flow_rate_y=-flowY/10000/dt`。
- 姿态角rad，gyro rad/s，加速度m/s²，速度m/s，位置m；`timespan`从us换算到s。

位置PD：

```c
control_x = 0.5f * (target_x - x_pos) - 0.7f * x_speed;
control_y = 0.5f * (target_y - y_pos) - 0.7f * y_speed;
pitch_add =  control_x;
roll_add  = -control_y;
```

上式实际输出还经过0.35rad限幅，接入位置控制时再经过附加角变化速率限制。Kp单位rad/m，Kv单位rad/(m/s)，没有新增位置积分项。

- 向右偏且仍向右运动：X误差负、速度正，Pitch需求应负，左压纠偏。
- 向前偏且仍向前运动：Y误差负、速度正，Roll需求应正，抬头向后纠偏。
- 运动中P项和速度阻尼共同决定结果，不能只用运动方向或一条日志判定输出正负。

## 接收、频率和时间戳

1. USART3 Normal DMA收原始字节块；ISR过滤HT，用FromISR队列接口复制字节、长度、RxTick与RxEpoch。
2. 初始化成功和ISR只请求接收；运行期间LC307任务拥有DMA启动与中止操作。
3. LC307任务拼帧，检查FE、0A、XOR和55；timespan的1000–60000us仍是待确认工程窗口，不新增猜测的quality阈值。
4. 控制任务目标200Hz，每5ms调用估计器；光流约50Hz，新序号才进行一次校正。权重保留0.95/0.05。
5. IMU软件快照包含姿态、gyro、加速度、Tick和序号。Tick为软件读数/发布时间，不是芯片硬件采样时间；当前没有IMU FIFO或历史环形缓冲。
6. 同一DMA块多帧可以共享接收Tick；不伪造时间戳，不重复累计恢复时间组，不用零sample_dt做跳变检查。
7. 接收时间、IMU时间和估计时间分开；预测不能让旧光流重新变新鲜。
8. 超过100ms没有有效光流时撤销可用标志，不清估计器内部位置、速度或previous speed；getter无效输出副本清零，调用方仍须判断valid。
9. 临界区只做快照和状态的短复制；计算、HAL和打印不放在临界区里。

## 位置环当前如何接入

`LC307估计 → Control_PositionHold → roll_target/pitch_target → Attitude_PID_Update → 角速度环 → 四路混控`。

- `mode=0`关闭，`1`等待，`2`已捕获目标并输出位置修正，`3`位置超差等锁存故障。
- 保留恢复帧与时间窗口、速度/倾角/偏航/跳变检查，失效撤销附加倾角，恢复后捕获当前位置。
- 退出位置辅助不等于自动停电机或自动降落。
- 手柄连接有效性目前还没有在 `PS2_SendControl()` 中阻止断连后的旧输入继续入队。因此队列新鲜度判断不等于已完整实现手柄断连保护，该项待处理，不能标记已验证。

## 当前提交是桌面计算验证状态

- `POS_DESKTOP_TEST=1`：复用正式位置控制器计算，但电机初始化和发送入口被编译条件禁用。
- START长按超过1秒开始计算，单击/双击停止；先等待上电静置校准完成，再长按开始。
- `position_hold_enable=1`；方向与尺度正式确认标志仍为0。桌面模式跳过正式0.42–0.58m高度及确认标志门限，其他数据有效性保护仍保留。
- LC307离桌面距离约0.5cm，换算高度为0.0050m。这不代表其工作距离和真实位移尺度已完成验收。
- 基础油门固定770档，用于与之前日志比较，不代表真实悬停油门，也不使用USB供电下的测量电压做推力拟合。
- 高度PID修正不参与本次桌面混控；打印的M1～M4是限幅后的候选命令，不是电机实测转速。
- 新增 `POS_MOTOR` 每秒打印5次。Radd/Padd单位mrad。手柄中立、数据有效并停稳后等待捕获目标。
- 不要仅把 `POS_DESKTOP_TEST` 改0就当作可飞成品：正式尺度、离地距离来源、运行开关、断连保护和实机验收仍要完成。

## Yaw零点与本次修正

已有两层参考：姿态算法减去上电的 `AttitudeZero.yaw`；控制任务静置5秒后把平均Yaw记为 `yawcontrol`。

以前START只清PID，没有把当前Yaw捕获为本次控制目标。本次增加 `yaw_capture_pending`：

1. 每次有效长按START置请求，包括运行期间重复长按。
2. 第一次真正进入控制，或存在请求时，执行 `yawcontrol=yaw`。
3. 清请求并继续保持该目标，不在每轮控制里覆盖目标。
4. 停止后再次开始，重新捕获本次航向。

这是航向目标捕获，不是重做IMU零点或gyro零偏标定。不能消除后续Yaw漂移，也不能代替磁力计或其他航向观测。无电机响应时，计算出的纠偏不会使机体自动回到目标。

## 如何阅读混控日志

当前 `FLIGHT_MIXER_MODE=1`：

```text
M1 = B - R - P + Y + H
M2 = B - R + P - Y + H
M3 = B + R + P + Y + H
M4 = B + R - P - Y + H
```

其中B是基础油门，R/P/Y是角速度环输出，H是公共高度修正；桌面模式H=0。

未触发限幅时，可从四路命令近似反推：

```text
B + H ≈ (M1 + M2 + M3 + M4) / 4
R ≈ (-M1 - M2 + M3 + M4) / 4
P ≈ (-M1 + M2 + M3 - M4) / 4
Y ≈ ( M1 - M2 + M3 - M4) / 4
```

存在整数截断，发生限幅后上述反推不再准确。M2/M4一组与M1/M3另一组的大差异通常主要来自Yaw，不能把它当成Pitch纠偏方向。变量m1～m4与物理端口之间还要考虑原有 `set_target(m3,m4,m1,m2)` 映射。
